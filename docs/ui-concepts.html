smabo-web UI 案

今の 9 タブ（Face / Sensors / two wheel mobile robot / Servo / Vision / Navigation / Motion Plan / Config / Log）を作り直すための 5 案と、それらを組み合わせたおすすめ案です。図はワイヤーフレームで、ダークは今の smabo-web の配色、ライトは新しく用意する配色です（右上で切り替え）。番号の付いた赤い丸は、下の説明と対応しています。
smabo は付いている部品が個体ごとに違う（スマホだけの構成もある）ので、どの案も「今つながっている部品に合わせて画面が変わる」ことを前提にしています（構成に合わせる）。また、機械学習などの機能をあとから足せる作りにします（機能を足せる作り）。

何を見て「付いている」と判断するか

部品判断のしかたあると出るもの
スマホ（必須）/app/… のトピック（カメラ・IMU・GPS・音声）が届いている顔・視線・会話・カメラ・Vision の振る舞い・IMU / GPS
ESP32/esp32/… が届く、または ESP32 の REST（/config）に応答があるステータスバーの esp32 ランプ、Config のうち ESP32 側の項目
車輪ESP32 の modes の dc_drive / encoder_drive、/odom が届くジョイスティック、軌跡、速度上限・min_duty の設定
サーボ（首・アーム）modes の servos と、設定にある関節のグループ、/joint_states首の操作・視線の首追従、アームパネル、MoveIt（アームの関節があるときだけ）
LiDARmodes の lidar、/scan が届くスキャン表示、地図（SLAM）、Nav2 のゴール指定

組み合わせで初めて出る機能もある。例: Nav2 は「車輪＋LiDAR」、Vision の「近づく」は「車輪」、「首で追う」は「首のサーボ」が必要。

作り方のルール

  • パネルは必要な部品を宣言する。例: Nav2 パネルは requires: ["wheels", "lidar"]。足りなければ出さない。モードも、中身のパネルが 1 つも出なければタブごと消す。
  • 途中で切れたら、消さずに灰色にする。走行中に ESP32 が落ちたときにパネルが消えると、配置がずれて誤操作につながる。「切断中」と表示して操作を無効にする。最初から無い部品のパネルとは区別する。
  • 手動で上書きできる。検出が間違っていたときや、まだつないでいない部品の設定を先にしたいときのために、設定で「この部品はある／ない」を指定できるようにする。
  • 機能が減っても空っぽに見せない。スマホだけでも、顔とカメラが大きく出る「対話」画面が主役になるようにする。

B デジタルツイン3D モデルはスマホとスタンドだけになり、クリックできる部位がほぼ無い。モデルを部品ごとに組み立てる仕組みが要る。●●●●●

拡張

機能をあとから足せる作り

機械学習のように、これから増える機能を画面の作り直しなしで足せるようにします。画面の骨組み（ステータスバー・メイン画面・右パネル・タイムライン）は固定し、機能はすべて「機能モジュール」として差し込みます。部品の有無への対応も、この仕組みでまとめて扱います。

モジュールが宣言するもの（例: 機械学習）

// src/features/ml/index.ts（案）
export default defineFeature({
  id: "ml",
  title: "機械学習",
  requires: ["phone"],                 // これが無ければ何も出さない
  optional: ["ml.detector", "ml.policy", "wheels", "servos.arm"],
  mode: { id: "learn", label: "🧠 学習" },   // 新しいモードを足す（既存モードに入れてもよい）
  panels: [DatasetPanel, TrainPanel, ModelPanel],
  overlays: [DetectionOverlay],          // メイン画面のカメラに重ねる
  commands: [{ label: "推論を開始", run: startInference }],  // ⌘K に出る
  timeline: ["/ml/events"],                // タイムラインに流す出来事
  settings: MlSettings,                  // 設定画面の一節
});

骨組みは features/ の一覧を読むだけ。機能を足すときはフォルダを 1 つ足し、既存のコードには触らない。

作り方のルール

  • 「できること」は部品だけでなくソフトも含める。STT・Nav2・MoveIt・学習済みモデルも、部品と同じ扱いで有無を判断する。brain 側に「動いている機能の一覧」を流すトピック（例: /smabo/capabilities、新設）を置くと、web が推測しなくて済む。
  • 差し込み口の数を絞る。モード・右パネル・メイン画面への重ね表示・ステータスのランプ・タイムライン・⌘K・設定の 7 つ。これ以外の場所はモジュールから触らせない。
  • モードもモジュールが足せる。ただし増えすぎないように、まずは既存の 4 モードに入れることを考え、作業の流れが別物のとき（学習のような）だけ新しいモードにする。
  • 重い処理は brain 側に置く。学習や推論は brain（または別マシン）のノードにして、web は表示と指示だけにする。web は ROS のトピック・サービス・アクションでやり取りするだけなので、モデルの中身が変わっても画面はそのまま。
  • モジュールを止められる。設定でモジュールごとにオン・オフできるようにして、使わない機能で画面が混まないようにする。

B デジタルツイン部位に結び付かない機能（学習・会話）の置き場所が無い。●●●●●

ガイドと合わせると良いこと

  • 各ガイドの「動作手順」の確認を「smabo-web に○○が出て動けば OK」と書ける。今の encmobile のガイドにある「Config タブで encoder_drive を有効にし、two wheel mobile robot タブ…」のような、タブ名に依存した説明が要らなくなる。
  • ステータスバーの「構成」を押すと、ロードマップの図に今できているノードを色付けして出せる。次に何をつなぐと何が増えるかがそのままわかる。
  • ロードマップにノードを足す（例: 機械学習）ときは、ガイド 1 ページと機能モジュール 1 つを同時に足す、という決まりにできる。

テンプレートの中身（例: 首振り）

// src/templates/neck.json（案）。大きさは比率で持つ
{
  "id": "neck",
  "name": "首振り",
  "guide": "https://…/guides/neck.html",
  "requires": ["esp32", "servos.head"],
  "layout": { "split": "row", "ratio": 0.6,
    "a": { "split": "column", "ratio": 0.65,
           "a": { "panel": "twin3d" },
           "b": { "panel": "camera", "props": { "behaviors": ["servo_follow"] } } },
    "b": { "split": "column", "ratio": 0.45,
           "a": { "panel": "servo.sliders", "props": { "joints": ["head_pan", "head_tilt"] } },
           "b": { "panel": "config",  "props": { "keys": ["modes.servos.head_pan"] } } } }
}

パネル（servo.sliders・config など）は共通の部品で、テンプレートは「どれを・どの設定項目だけ・どの比率で」並べるかだけを持つ。Config パネルは keys で表示する項目を絞れるので、ガイドで触る設定だけが出る。

決まりごと

  • 標準テンプレートは書き換えない。大きさや並びを変えたら「自分のテンプレート」として別に保存する。いつでも「標準に戻す」ができるので、ガイドの画面写真と食い違わない。
  • ガイドから直接開ける。各ガイドに「smabo-web で開く」ボタンを置き、http://localhost:5173/?template=neck のようにテンプレートを指定して開く。ガイドの「Config タブの Modes/servos で…」のようなタブ名の説明が、「開いた画面の右下で…」で済む。
  • 部品が足りないときも開ける。使えないパネルは「○○が見つかりません（つなぎ方: ガイドの配線の節）」と表示して残す。ガイドを進めている途中で、まだ配線していない状態でも開けるようにするため。
  • テンプレートの追加はガイドの追加と同時に。ロードマップにノード（例: 機械学習）を足すときは、ガイド 1 ページ・機能モジュール・テンプレート 1 つを同時に足す。
  • ふだん使い用のテンプレートも少し用意する。ガイド用とは別に「全部入り」（おすすめ案 A+B+C の画面）と「デモ」くらいを置き、構成に合わせて使える方を最初に開く。

決まりごと

  • 最初は OS に合わせる。prefers-color-scheme に従い、「自動・ライト・ダーク」をステータスバーで選べる。選んだものはブラウザに保存する。
  • 色は必ずトークン（CSS 変数）で書く。今の src/index.css は --bg などのトークンを持っているので、ライト用の値を足せば大半は切り替わる。機能モジュールも直接色を書かない決まりにする。
  • canvas と 3D は別に対応が要る。CSS 変数が効かないので、今は TrailMap・GazePad・Joystick・Plan・viewer3d（three.js）・Vision に色が直接書いてある。getComputedStyle でトークンを読み、テーマが変わったら描き直すようにする。
  • テーマで変えないもの。カメラの映像、スマホの顔のプレビュー（スマホの画面そのもの）、緊急停止の赤。緊急停止はどちらのテーマでも一番目立つ色のままにする。
  • ライトでは色を少し濃くする。シアン・オレンジ・赤は白い背景では薄く見えるので、文字に使っても読める濃さに下げる（このページのライトの値）。
  • 使い分けの目安。屋外や明るい展示会場でタブレットを使うときはライトが見やすい。夜や暗い部屋での実験はダーク。
  • ガイドの画面写真はダークで揃える。テンプレートと同じく、ガイドに載せる写真は 1 つのテーマに決めておく。
